# coverage floor — the minimum total line coverage (%) the host unit-test suite
# must hold over firmware/Src, scoped to match test-coverage-plan.md's baseline
# methodology (.cpp/.c TUs only; headers excluded via -ignore-filename-regex).
# This is a REGRESSION FLOOR, not a target: coverage is expected to GROW as the
# plan's phases land, and the floor is ratcheted UP after each phase.
#
# Baseline as of Phase 1 (test-coverage-plan.md quick wins): 30.07% lines
# (3758 / 12498), measured by `make test-cov` on branch test/coverage-phase1
# (Phase 0 was 12.45%; the 5 Phase-1 suites — event_scheduler, LfoStepSeq,
# LfoOsc, MixerState, FxBus — lifted it past the >=30% Phase-1 gate). The floor
# is set at 29 (integer) to leave a ~1-pt buffer against benign line-count
# churn (a TU restructured at the same coverage) flapping the gate. See
# _bmad-output/planning-artifacts/test-coverage-plan.md.
#
# How CI uses this (scripts/ci/coverage-gate.sh):
#   - llvm-cov report runs scoped to firmware/Src (headers excluded), same scope
#     as `make test-cov`.
#   - the TOTAL line coverage % is parsed and compared to this floor.
#   - measured < floor  -> REGRESSION -> CI FAILS.
#   - measured >= floor -> PASS.
#
# To ratchet the floor UP after a coverage phase lands:
#   1. make test-cov                         # fresh measurement
#   2. read the TOTAL % from build/test-cov/coverage-report.txt
#   3. set the integer below to just under the new measured % (leave a buffer)
#   4. commit the floor bump in the same PR that lands the coverage.
#
# The floor MUST be a single integer on its own line (the gate script grep-matches
# the first line that is only digits). Comments (#) are ignored.

29
